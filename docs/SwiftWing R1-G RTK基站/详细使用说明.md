# SwiftWing R1-G RTK 基站使用手册

文档版本：V1.0 | 更新日期：2026-11-12

适用硬件：SwiftWing-UM982 V1.0 基站，固件 0.1.23 及同系列 0.1.24 配置接口。
配套软件：SwiftWing QGC Windows 0.1.0 build8。新增 2S 供电板按 2026-11-12 网表及用户确认的 XT30 连接说明。

实际版本以设备读回为准，不因教程发布自动升级设备。新刷通用固件、恢复设备参数后默认角色是移动端，不能把它当已建好的基站；升级保留原参数，不会自动把原基站改成移动端。

## 一、最快开始：先用 USB 跑通差分

1. 将 GNSS 天线接基站 **ANT1**，放在室外开阔处，固定好支架。基站输出差分不要求 ANT2 组成双天线。
2. 用支持数据的 USB 线，将 **RTK 主板 USB** 接电脑。新增供电板的充电 USB 不是 QGC 数据口。
3. 打开 SwiftWing QGC，进入 **应用设置 → NTRIP/RTK → SwiftWing R1 / R1-G RTK**。
4. 在 **RTK 设备** 选对硬件短码；使用方式选 **基站：自动测量**（`RTK_ROLE=1`），测量时间先用 120 秒，点击 **应用并保存**，等待生效和读回确认。
5. 在局域网配置中确认路由为 **AUTO · QGC USB 优先，否则 UDP**，点击 **保存局域网设置**。当前 B8 通过 USB 会话自动协商 USB 差分，不必把保存出口掩码机械改成 4。
6. 保持基站天线不动，等待 **基站 RTCM 已就绪**，并看到 **QGC 实收** 有效帧持续增长、帧龄新鲜。120 秒不是从插电起保证完成的倒计时。
7. 接通目标飞控 USB 或遥测，勾选 **将 QGC 收到的差分注入已连接飞控**；移动端经 CAN 接飞控。分别确认移动端收到 RTCM 及接收机解状态，不能只看基站图标变绿。

### 1. 三段链路各看一项证据

| 环节 | 应确认的结果 | 不能代替它的现象 |
| --- | --- | --- |
| 基站接收机 → 基站输出 | RTCM 就绪、新鲜参考和观测数据 | PPS 绿灯、开机计数 |
| 基站 → QGC | 有效 RTCM 帧增长、CRC 及帧龄 | USB 设备已识别、Wi-Fi 已关联 |
| QGC → 飞控 → CAN 移动端 | 移动端 RTCM 增长/龄新鲜、有效定位解 | 仅基站发送计数或 QGC 图标绿色 |

### 2. 电脑软件

使用本项目 **SwiftWing QGC 0.1.0 build8**。当前安装器位于 `D:\SwiftWing-QGC-Windows-0.1.0-b8\SwiftWing-QGC-Setup-0.1.0-b8-Windows-x64.exe`。其他电脑复制完整安装器安装，不只复制单个 EXE。官方普通 QGC 不包含本项目配置页。

当前配置不需要 BOOT 长按或进入下载模式。

## 二、供电、充电与开关

用户确认的实体连接为 **供电板 SYS_SW_OUT → RTK 主板 XT30**。供电板两只 18650 串联；两节 2200 mAh 串联后仍为 2200 mAh，电压相加，不是 4400 mAh。

```text
2S 18650 → 供电板电源选择 → SW1 船型开关 → SYS_SW_OUT → RTK 的 XT30
供电板充电 USB → CH224A 快充协商 / TP5100 充电 → 电池及负载供电路径
RTK 主板数据 USB → 电脑 QGC（与供电板充电 USB 分开）
```

### 1. 两个 USB 与 XT30 不要混淆

| 接口 | 用途 | 要点 |
| --- | --- | --- |
| 供电板 USB-C | 充电、快充输入 | 不连接 ESP32，不会枚举 RTK 双串口 |
| RTK 主板 USB-C | QGC 配置、USB RTCM、5 V 供电 | 需数据线；可在开关关闭后继续给主板供电 |
| RTK 主板 XT30 | 接供电板开关后输出 | 走主板降压路径，不是 USB/CAN 的 5 V 脚 |
| RTK 的 CAN_5V | 外部 5 V 输入 | 不能接 2S 电池或快充 12 V |
| FAN+ / FAN- | 受控风扇回路 | FAN- 不能再搭到 GND，否则绕过温控 |

网表中 CH224A 通过 24 kΩ 配置请求 12 V；TP5100 设置为 2S、约 8.4 V 充电。使用与设计匹配、支持 12 V 档位的快充电源和线材；普通 5 V 电源不能据此保证两节充满，不擅自切换到 15/20 V 输入。[P1][P2]

RTK 主板 XT30 经反接保护、TPS54302 降压和电源选择进入公共 5 V；2S 电池及设计 12 V 输入处于该降压芯片推荐输入范围，但不因此声称整机所有输入范围、温升或最大负载都已验收。[P3]

### 2. 边充边用和开关边界

该电路提供充电时继续给 RTK 供电的路径。开关控制 **本供电板到 XT30 的负载支路**：关掉 SW1 时，RTK 若还连接主板 USB 或带 5 V 的 CAN，仍可能正常运行；这不是开关失效。外部电源插拔是否完全不重启，仍需负载实测，不能当作已验收 UPS 无缝切换。

充电、保护、均衡和低压报警电路仍接电池，SW1 关闭不等于电芯完全隔离，仍有待机消耗。供电板充电指示灯由硬件决定；绿灯不证明两节电池完全均衡，也不是 QGC 可配置的充电截止条件。

### 3. 低压报警与后台读数

LM393/TL431 分压设计报警点约 7.0 V，用户实测在 7.03 V 附近开始响。间歇响转长鸣的时间规律不能由本网表直接认定为固件定时策略；这是供电板硬件蜂鸣器，和 RTK 主板蜂鸣器不同，RTK 的 `BEEP_ENABLE` 不控制它。

网表没有将电池总压、两节电压、充电状态或电量计接到 ESP32。QGC 的 USB/CAN 5 V 检测不是 2S 电池遥测，不能显示电池百分比或证明已充满。低压报警后应结束作业并补电，不把保护器件最终断电当作正常续航终点。

## 三、建站方式与必要参数

### 1. 自动测量：新地点没有可靠坐标

在 QGC 选择 **基站：自动测量**，打开 **基站坐标与测量**，核对站号、测量时间，保存。天线保持静止并等待接收机具备测量条件和持续观测，室内或窗边无法仅靠延长时间保证建站。

| 参数 | 初始/设置值 | 含义 |
| --- | --- | --- |
| `RTK_ROLE` | `1` 自动测量；`2` 固定坐标 | `0` 是移动端 |
| `BASE_ID` | 默认 `0`；范围 `0–4095` | 同一差分流的站号，避免混用多个基站 |
| `BASE_SURVEY_S` | 默认 `120`；范围 `60–3600` 秒 | 不是绝对坐标精度承诺 |
| `BASE_SET` | 固定坐标时确认 `1` | 仅表示用户确认，不证明坐标准确 |
| `BASE_LAT_E8` | 纬度° × 100000000 | 北正南负，整数 |
| `BASE_LON_E8` | 经度° × 100000000 | 东正西负，整数 |
| `BASE_H_MM` | WGS84 椭球高 × 1000 | 单位毫米，不直接填海拔/MSL |
| `RTCM_UDP_PORT` | `13320` | 与 QGC UDP 输入一致 |
| `RTCM_TCP_PORT` | `2101` | 基站 TCP 服务端端口 |

自主平均不等于可靠控制点坐标；每次重启会重新测量，重复作业的绝对参考可能变化。需要统一参考坐标时，使用经过核验的已知坐标。无论哪种模式，工作时都不要移动基站天线。

### 2. 固定坐标：已有可信控制坐标

选择 **基站：固定坐标**，输入实际 ANT1 对应参考点的纬度、经度和高度，明确确认 `BASE_SET`，再保存、读回。当前代码设置 UNDULATION 为 0，按 WGS84 椭球高下发；不得直接复制地面站海拔/正高，也不得把地面控制点高度未经天线高换算就当接收机天线参考点。

单位示例：纬度 31.12345678° 填 `3112345678`，经度 121.12345678° 填 `12112345678`，椭球高 100.123 m 填 `100123`。它们只说明单位，不是可用于现场的坐标。本板没有另一个可自动修正天线安装高度的参数。

### 3. 保存与输出速率

修改后点击 **应用并保存**，等 **参数已实时生效、保存并读回确认**。网络路由和 Wi-Fi 另点 **保存局域网设置**。角色、坐标或站号变更可能重新配置 UM982 并短暂中断差分，不在作业中随意修改或发送 `FRESET`。

当前基站默认参考帧 1006 约 5 秒、设备信息 1033 约 10 秒；1074/1084/1094/1124 观测约 1 Hz。`GPS1_RATE_MS` 属于移动端定位发布设置，把它改成 50 ms 不会把基站 RTCM 变成 20 Hz，也不是提高差分精度的办法。

## 四、差分输出方式

基站差分可通过 USB、无线 UDP 或原始 TCP 输出。默认路由为 **AUTO**：有有效 QGC USB 会话时优先 USB，否则走 UDP。

- USB 输出与 QGC 自动识别的操作见 [USB 与地面站输出差分](USB与地面站输出差分.md)。
- 无线 UDP 与原始 TCP 的操作见 [Wifi 输出差分](Wifi输出差分.md)。

| 手动出口 | mask 位 | 说明 |
| --- | --- | --- |
| UDP → 局域网目标 IP | `1` | 主动发给目标地址；空目标使用对应网络广播 |
| TCP → 等待接收端连接 | `2` | 接收端连接基站 IP:2101，当前最多两个客户端 |
| USB → QGC 自动读取 RTCM | `4` | 原生 USB RTCM 接口 |
| CAN → 移动端 | `8` | 特定直连方案；经飞控转发时不需要 |

组合值相加。保存 mask 只在手动路由生效；AUTO 的有效出口是 USB 4 或 UDP 1，保留的 mask 可能不同。不要为追求「全开」而无目的勾选全部出口。

## 五、状态、指示灯与温控

### 1. 判断差分是否就绪

查看「基站」页的 RTCM 就绪、报文新鲜度及各出口计数，不只看坐标或卫星数。就绪要求近期有匹配站号的 `1006`，并有新鲜的 MSM4 观测；只有描述报文或历史计数增加过，不代表当前仍有可用差分，观测中断后就绪状态会失效。

出口计数表示数据交给对应接口或队列，不是接收端确认。

### 2. 指示灯

- **红灯**：接收机尚未配置、ERR 告警或温度采样异常等故障条件存在。
- **绿灯**：在无上述故障时，基站 RTCM 已就绪。
- **蓝灯闪烁**：运行中长按 BOOT 约两秒开启临时维护/无线窗口，约 30 分钟。基站正常配置和联网不依赖该窗口。
- **PPS 灯**：反映接收机 PPS 脉冲，不单独证明基站差分可用或接收端已固定。

绿灯不表示飞机已获得 RTK 固定解，接收端需另外核验。QGC 中三脚架图标颜色只反映基站接收条件：已识别 USB 基站但没有有效差分时显示红色，新鲜 RTCM 且基站就绪时为绿色。图标展开可看 **差分接收、基站就绪、基站卫星 / 跟踪、飞控 GPS 卫星 / 解状态、目标飞控 RTK 反馈、温度 / 风扇**，点击 **SwiftWing RTK 配置** 进入对应基站。图标绿色不要求飞控已经 RTK Fixed，也不代表移动端航向或 EKF 已融合。

### 3. 温度、风扇和蜂鸣器

| 参数 | 初始值 | 允许范围 | 说明 |
| --- | --- | --- | --- |
| `FAN_ON_C` | `50` | `20–85` °C | 风扇开启阈值 |
| `FAN_OFF_C` | `45` | `10–84` °C | 风扇关闭阈值，必须低于开启温度 |
| `BEEP_ENABLE` | `1` | `0` / `1` | 主板蜂鸣器，不控制供电板低压报警蜂鸣器 |
| `AP_ENABLE` | `1` | `0` / `1` | 控制基站热点策略；保存外部 Wi-Fi 后使用 AP+STA，不能把设为 `0` 视为彻底关闭热点 |

后台风扇状态是控制输出，没有转速检测。显示开启仍需确认风扇实际接线和运行；显示关闭但始终转动时，检查 FAN- 是否被直接接地。

温度为板载 NTC 的近似读数，不是电芯温度；USB/CAN 5 V 读数不是电池电量。供电板低压报警与主板飞控状态蜂鸣分开。

### 4. 供电显示

后台分别显示 USB 及 CAN 5 V 入口检测值。两路经过电源合路电路，数值用于诊断，不代表存在固定的 USB/CAN 优先级，也不能只凭读数或显示大小判断哪一路承担负载。异常读数应结合实际供电、接线及必要的电表测量核对。

## 六、日志记录与导出

QGC 点击 **打开设备日志与会话导出**，网页中 **刷新状态与会话** 后选择单会话或全部，点击 **下载所选 .swlog**。Flash 外场记录每次启动默认约 1 Hz、容量名义约 104 分钟，写满覆盖最早记录，回来及时导出。

网页导出临时停止并尝试恢复原记录状态，下载后核对是否仍在记录；断连、失败或原来已停止时不能假定自动继续。独立调试工具可能保持冻结。清空前先备份，等待擦除完成，之后点开始记录或重新上电。

「日志记录」中的系统事件用于排查启动、USB、网络、接收机及升级等事件，保留本次开机最近 24 条精简记录，重启清空；与 Flash 会话日志不同。本电源板没有电池遥测，以上日志不能补出单节电压、充电电流或电量曲线。

`.swlog` 是专用记录文件，不是连续原始 RTCM、RINEX 或完整接收机原始观测文件。配套离线解码工具可转换为 CSV 和摘要 JSON；普通用户可以直接将原始文件交给技术支持。

## 七、UM982 工具与恢复设置

「UM982 工具」可发送一条原厂命令并读取回执，用于诊断或有明确依据的配置。查询示例为 `VERSIONA`、`MODE`、`CONFIG`。普通建站优先使用基站页面，ESP32 会按保存参数自动配置接收机。手工修改串口、输出列表或工作模式可能打断当前差分，且不一定同步回 ESP32 参数。

两个恢复入口含义不同：

- **恢复设备参数**：恢复 ESP32 的通用参数，角色会回到移动端，风扇阈值回到 50/45 °C；之后需重新选择基站。外部 Wi-Fi 凭据另存，不随此操作自动清除。
- **UM982 恢复出厂**：向接收机发送 `FRESET`，随后 ESP32 重新下发当前工作角色，期间数据会中断。它不是清空全部设备网络设置。

清除外部 Wi-Fi 应在「局域网」清空名称并保存。按 BOOT 或 EN 不等于恢复出厂。

## 八、固件升级

常规升级优先使用网页或配套 USB 后台：

1. 保存设备序列号、当前版本和关键参数；有需要的日志先导出。
2. 获取适配本硬件的应用镜像，文件名通常以 `_app.bin` 结尾。
3. 打开「固件升级」，核对目标设备身份，选择镜像，点击「上传并升级」。
4. 保持电源和连接稳定，等待上传、校验和重启。
5. 重新连接，核对显示的新版本、工作角色、网络及参数，并重新确认 RTCM 就绪与接收端数据。

升级使用备用应用分区，并校验芯片、项目及镜像完整性。常规应用升级保留已有参数；仍应在升级后回读确认。完整烧录镜像不能代替应用镜像上传，也不要上传其他产品或飞控的固件。

只有应用无法恢复、安装启动程序或明确要求串口烧录时才使用下载模式：按住 BOOT，点按并松开 EN/RESET，再松开 BOOT。普通参数修改和网页升级不需要此步骤。

## 九、每次作业检查

1. ANT1 固定、无遮挡；基站和支架没有在建站后移动。自动测量或已知坐标模式与现场一致。
2. 电池与电源连接正确，无低压报警。需要 SW1 关机时，核对主板 USB/CAN 是否还提供外电。
3. QGC 选对基站硬件码，角色、站号、坐标及路由读回正确。
4. 接收机显示 RTCM 就绪，QGC 有效帧增长、CRC 没有持续报错、帧龄新鲜。
5. 差分注入对象和反馈绑定符合本轮目标，移动端收到 RTCM，目标 GPS 达到本次任务要求的解状态。绿色基站图标不能单独作为放飞判据。
6. 无线时检查 QGC 主机 IP、UDP 目标、端口、信号和实际可达性；USB 测试时不被 AUTO 切路误导。
7. 板温、风扇及告警状态正常。
8. 需要留档时及时停止并导出记录，异常附现场说明。

## 十、常见问题

| 现象 | 排查要点 |
| --- | --- |
| 接 USB 不识别基站 | 是否误插供电板充电口；检查 RTK 数据线、实际 USB 方向、串口占用及设备身份 |
| 等待 valid RTCM3 | 查角色、测量条件、RTCM 就绪、配置/RTCM 接口；不要盲改 UM982 波特率 |
| 插 USB 后 UDP 没数据 | AUTO 可能优先 USB 并关无线；断主板数据 USB 或明确手动 UDP |
| TCP 连不上 | 手动模式启 TCP、正确基站 IP、端口、同网和防火墙；不是 NTRIP 账户问题 |
| Wi-Fi 连上但 QGC 收不到 | 查 QGC 电脑目标 IP、UDP 监听开关/端口、防火墙及客户端隔离 |
| 显示设备名但无后台 IP | 查真实 LAN 连接和无线省电；未知 UDP 身份不一定能显示本设备后台 |
| 绿图标但飞控没 Fixed | 图标只证明其接收条件；逐段查飞控转发、CAN、移动端差分龄和 GNSS 质量 |
| 风扇一直转 | 核对温度/阈值，FAN- 是否额外接 GND；不要用电池温度猜板温 |
| 关 SW1 后 RTK 还运行 | 主板 USB 或 CAN 仍可能供电；关的是 XT30 支路，不切其他电源 |
| 绿充电灯但单节不一致 | 绿灯不等于均衡合格；分别测两节及同参考点总压，核对充电/均衡动作 |

## 附录A：供电 PCB 待机实测记录

# RTK 主板硬件、接口与线序

适用 SwiftWing-UM982 V1.0 主板，依据 2026-11-04 网表及当前固件核对。R1 移动端与 R1-G 基站共用此主板；基站选配 2S 供电板见[基站供电说明](../SwiftWing%20R1-G%20RTK基站/供电与充电.md)。

UM982 负责 GNSS 定位和双天线定向，ESP32-S3 负责配置、CAN / USB / 网络通信、有效性检查、温控和日志。**本板没有外置磁罗盘**，不能按带磁罗盘 GNSS 的线束和参数接入。

## 接口一览

| 接口 / 部件 | 功能 | 使用要点 |
| --- | --- | --- |
| ANT1 | 主天线：定位与基站参考；双天线定向的主天线 | 基站只需接此口；移动端正常前后安装时置于机头侧 |
| ANT2 | 第二天线：移动端定向 | 与 ANT1 使用同型号多频有源天线、刚性固定 |
| 主板 USB-C | 5 V 供电、双虚拟串口 | 接电脑 SwiftWing QGC，使用数据线 |
| CAN，U7 | 5 V 电源及 DroneCAN | 移动端日常接飞控；信号为 CANH / CANL |
| UART0，U29 | ESP32 调试 / 救援 | 3.3 V TTL 信号，不是 UM982 GNSS 串口 |
| XT30 | 电池 / 配套供电板输入，经主板降压 | 与 USB / CAN 5 V 输入不同，按实物极性接线 |
| FAN+ / FAN− | 5 V 受控风扇 | FAN− 必须经过板上控制，不能额外接地 |
| BOOT / EN | 应用维护窗口、复位及下载模式 | 普通改参不需要进入下载模式 |
| 状态灯、PPS 灯、蜂鸣器、NTC | 运行提示、脉冲指示、板温 | 指示不替代接收端数据和解算状态 |

天线口提供约 3.3 V 直流馈电，选用明确支持此电压和所需频段的有源 GNSS 天线。不要向射频中心针外接电源；相同射频接头不代表电气兼容。

## CAN 四针线序

下表按 **PCB 连接器 U7 的电气针号**说明，未指定“从插头正面看由左到右”。插头与插座观察面可能镜像，先找实物 1 脚标记或核对随货线束；不只按线色判断。

| U7 针号 | 信号 | 接飞控 |
| --- | --- | --- |
| 1 | CAN_5V，外部 5 V 输入 | 对应 5 V 电源，确认飞控端供电能力 |
| 2 | CANH | CANH |
| 3 | CANL | CANL |
| 4 | GND | GND |

两端同名相连，CANH / CANL 不按 UART 的 TX / RX 交叉。USB 单独供电也仍需正确连接总线参考地。CAN_5V 只接 5 V，不能接 2S 电池原始电压、12 V 快充或飞行动力电池。

默认速率 1 Mbps，CAN 信号线使用双绞线、尽量短的支线。主干两端各一个 120 Ω；本版板上 R69 是装配决定的固定终端，不能软件关闭。装机前核对是否已装，不再重复加第三个终端。全部断电后测 CANH 与 CANL，两个 120 Ω 并联约为 60 Ω。

## UART0 四针线序

按 **PCB 连接器 U29 电气针号**，信号方向相对于 RTK 主板：

| U29 针号 | 信号 | 维护时连接 |
| --- | --- | --- |
| 1 | 公共 5 V 电源 | 不与 USB-UART 的 3.3 V 电源脚直接混接 |
| 2 | ESP32 TX，GPIO43 | USB-UART 的 RX |
| 3 | ESP32 RX，GPIO44 | USB-UART 的 TX |
| 4 | GND | USB-UART 的 GND |

**电源针 5 V 不表示串口信号允许 5 V。** 调试器使用 3.3 V TTL 逻辑；已独立供电时，先仅接 TX / RX / GND。U29 没有自动下载用 DTR / RTS 到 BOOT / EN 的连线。

此口不要接到飞控 GPS1 / GPS2 后套用其他厂商的 UM982 串口教程。本板推荐的飞控接口是 CAN；板内 UM982 COM1 / COM2 已连接主控。各口实际协议见[接口数据与差分链路](接口数据与差分链路.md)。

## 电源、风扇与按键

USB、CAN 5 V 与 XT30 降压支路经电源合路供主板使用。关闭基站供电板开关时，如果主板 USB 或 CAN 仍供电，主板可能继续运行。USB / CAN 入口电压读数不表示固定优先级，也不是电池电量。

风扇接 FAN+ / FAN−，不要把 FAN− 再搭接 GND。基站按本手册保存 **FAN_ON_C=35、FAN_OFF_C=30**后，板温达到 35 °C 开、降至 30 °C 或以下停；移动端不按基站策略开风扇。状态显示是开关控制输出，没有风扇转速测量。

应用正常运行时长按 BOOT 约 2 秒可开启约 30 分钟的临时无线维护窗口，重启失效；它不同于保存的“无线高级维护”。按住 BOOT 再复位则进入芯片下载模式，日常 USB 参数配置不用这样操作。EN / RESET 是复位，不是清空保存参数。

## 状态灯如何理解

- **红灯**：接收机尚未配置、ERR 或温度检测异常等故障条件。
- **绿灯**：移动端表示新鲜位置固定解；基站表示 RTCM 就绪，均需结合故障状态判断。
- **蓝灯闪烁**：临时维护窗口提示，不是“所有配置已保存”的指示。
- **PPS 灯**：接收机脉冲指示，不代表差分传输、双天线航向或飞控融合成功。

移动端绿灯不证明航向有效，基站绿灯也不证明飞机已 RTK Fixed。进一步安装见[移动端硬件安装](../SwiftWing_R1_RTK_移动端/硬件安装.md)或[基站硬件功能与接口](../SwiftWing%20R1-G%20RTK基站/硬件功能与接口.md)。
